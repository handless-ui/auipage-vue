文档/概念/前端工具

Concept 04前端工具

工具让智能体"动手做事"。后端工具在服务端执行、页面只展示过程；前端工具在浏览器执行，还能挂一个 Vue 组件与用户交互。

defineToolToolRenderPropsVue 组件
01

defineTool

tools/getBrowserTime.ts
import { defineTool } from "@auipage/vue";

export default defineTool({
    name: "getBrowserTime",
    description: "获取当前浏览器所在设备的本地日期与时间",
    parameters: { type: "object", properties: {}, required: [] },
    execute() {
        return new Date().toLocaleString();
    },
});
字段必填说明
name是工具名，对应模型工具描述里的 function.name。
description是给模型看的说明，写清“什么时候该用”。
parameters是入参 JSON Schema，无入参也要给空的 object。
execute否页面侧执行函数，可同步或异步；省略时按空执行兜底。
render否Vue 交互组件；缺省时 execute 的返回值就是最终结果。
02

render 组件的 props

实时态与历史回读态共用一套 props，组件既能交互、又能只读回显：

types.ts
interface ToolRenderProps {
    args: any;                                  // 模型解析出的入参
    result?: any;                               // execute 的结果（异常时为错误对象）
    status: "pending" | "success" | "error";    // execute 状态
    call?: (result: unknown) => void;           // 【实时态】交还结果、结束挂起
    uiResult?: unknown;                         // 【历史回读】当时交还的结果
    uiStatus?: "success" | "error";             // 【历史回读】交互状态
}

判断规则只有一条：有 call 是实时态，没有 call 是历史只读态。

03

交互式工具示例

tools/askFavoriteFruit.ts
<script setup lang="ts">
import { defineTool } from "@auipage/vue";
import FruitPicker from "./FruitPicker.vue";

const FRUITS = ["苹果", "香蕉", "橙子", "葡萄", "西瓜"];

export default defineTool({
    name: "askFavoriteFruit",
    description: "当需要了解用户喜欢什么水果时使用",
    parameters: { type: "object", properties: {}, required: [] },
    execute() { return FRUITS; },
    render: FruitPicker,
});
</script>
FruitPicker.vue
<template>
    <!-- 历史回读：没有 call，只读展示 -->
    <span v-if="!call">已选择：{{ uiResult }}</span>

    <!-- 实时交互：拿到 execute 的候选列表 -->
    <div v-else class="fruit-picker">
        <p>请选择你喜欢的水果：</p>
        <button
            v-for="fruit in (typeof result === 'object' ? result : [])"
            :key="fruit"
            type="button"
            @click="call(fruit)"
        >{{ fruit }}</button>
    </div>
</template>

完整链路：execute 拿候选 → core 把 { render, status, result } 交给页面 → 卡片进入 executing 并挂载组件 → 用户点击 → call(fruit) → core response("tool-result", ...) 回传后端 → 再次回调写入 uiResult，组件转只读留在页面上。

04

生命周期

phase
pending → executing → result
phase触发表现call
pending流中首次收到 tool-call名称 + 入参 + 运行中无
executing带 render 的工具 execute 完成挂载 render 组件有
result后端工具 / 无 render 工具结束结果卡片无

带 render 的工具在交互完成后仍然停在 executing： call 被清空、uiResult 写入，组件自然切到只读态，节点不重建。

05

历史回读与后端工具

  • 工具仍注册：历史里还原为只读 executing，用 uiResult / uiStatus 驱动。
  • 工具已下线或无 render：降级为 result 形态的结果卡片。
  • 后端工具：对页面透明，流里同样是 tool-call 但没有 render，直接 pending → result，无需注册。
所以 render 组件必须处理两种态。只写实时分支、忽略 !call， 历史会话里这块工具就会渲染失败。
