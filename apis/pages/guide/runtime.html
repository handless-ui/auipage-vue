Concept 05数据流与状态

core 只管流程，runtime 把命令式回调翻成状态更新，Vue 组件订阅 store 渲染。三层分工，互不知道对方的实现细节。

01

四层结构

layers
Vue 组件层          ChatContent.* / ThreadList.*
      ▲ 订阅 store           │ 调 aui.* 触发动作
      │                      ▼
状态层             store（messages / threads / isExecuting ...）
      ▲ setState             │
      │                      ▼
运行时层           makeChatContentRuntime / makeThreadListRuntime
      ▲ 命令式回调           │
      │                      ▼
编排器层           AuiPage（@auipage/core）

Vue 版没有引入额外状态库：runtime 直接维护一份可响应的状态对象， 组件用 computed / 渲染副作用订阅它。

02

状态形态

store.ts
interface AuiState {
    messages: ChatMessage[];             // 当前会话消息
    threads: ThreadListItem[];           // 会话列表
    activeThreadId: string | undefined;  // undefined 表示新建会话
    isExecuting: boolean;
    composerValue: string;
}
03

append 的翻译规则

  • text / loading / thinking：并入最后一条同 role 消息的 parts（不存在则新建）， 并返回一个增量函数，后续片段直接往 text 上拼。
  • tool-call：先建 pending part（稳定 id），返回结束回调； 再按有无 render 走 executing 或直接 result。
  • 其它 type：原样追加。
同 role 合并是硬约束。实时态与历史回读因此结构一致，同一套模板能吃两种态。
04

一次发送的链路

  1. 输入框或发送按钮触发 sendMessage(aui, state)。
  2. trim 为空或 isExecuting 为真时直接 return；否则清空输入、置执行中。
  3. AuiPage.sendMessage：append 用户消息 → ThreadList.new（新会话时）→ MessageHistory.append → 调 ChatTransport.run。
  4. core 消费 generator：文本增量拼接、tool-call 建 part、终态按 render 分支。
  5. generator 结束，Promise resolve，执行中复位，发送按钮恢复。

Viewport 订阅消息数量与片段文本总长度，所以流式增量也会触发滚到底。

05

多实例与错误

  • 隔离：不同 Provider 各有独立 store 与 AuiPage，同一页面可以并排多套（多账号多窗口）。
  • 重复发送：sendMessage 内部 catch core 的 reject，只 console.error。
  • 上下文缺失：组件在 Provider 之外使用会抛错并给出修复提示。
